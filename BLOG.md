# Обновление блога

## Редакционные правила сайта

При переносе постов из Telegram адаптируйте текст для сайта: не добавляйте
призывы поставить лайк, реакцию, «огонёк», «тыкнуть» и аналогичные обращения
к механикам канала. Такие фразы удаляются, даже если они есть в оригинале поста.
Не дублируйте призывы подписаться на канал: на странице уже есть кнопки
Telegram и MAX. Смысл поста и полезные ссылки сохраняйте.

## Сборка и публикация

Просмотры Telegram обновляются автоматически ежедневно в 00:00 по Москве
и при публикации изменений через `.github/workflows/deploy.yml`.
Запуск GitHub Actions может задержаться. Источник — публичный виджет поста,
ссылка берётся из `BlogPosting.isBasedOn` каждой статьи; ключи API не нужны.
При ошибке сохраняется предыдущее значение. Полный сбой отмечается в Actions,
но не мешает публикации сайта. Счётчики публикуются на Timeweb и GitHub Pages.
Ручное обновление: `npm run update:views`, затем `npm run build`.
Telegram округляет большие значения (например, `1.37K`); это не посещения сайта.

Общий источник данных — `data/articles.json`. Из него команда `npm run build`
формирует последние 3 карточки главной, полный `/blog/`, его SEO-список
и каталог связанных материалов в `js/article.js`. Сортировка — по `published`
в формате YYYY-MM-DD, новые первыми. Дизайн задаётся существующим CSS.

При добавлении статьи создайте `blog/<slug>/index.html` с BlogPosting
(headline, description, datePublished, image), изображением и категорией.
Запустите `npm run build`: новая страница автоматически попадёт в общий каталог
и все списки. При необходимости отредактируйте краткое описание, категорию
или просмотры в `data/articles.json` и повторите сборку. Уже существующие записи
редактируются в этом каталоге; тексты и SEO самих статей остаются в их HTML.

Перед публикацией выполните `npm run check` и `npm test`. Публикуйте вместе
обновлённые `index.html`, `blog/index.html`, `js/article.js`, `sitemap.xml`,
страницу новой статьи, оригинал и созданные WebP-производные.
HTML-списки доступны без JavaScript. Сборка не требует сторонних пакетов.

## Изображения

После добавления статьи в каталог выполните `node scripts/optimize-images.cjs`
(требуется sharp; его модуль можно передать через `SHARP_MODULE`), затем
обязательно `npm run build`. Генератор использует изображения из
`data/articles.json`, не изменяет оригиналы и не делает AI-перерисовку,
ретушь или кадрирование. Разрешение не увеличивается; пропорции сохраняются.

- `img/blog/thumbnails/` — миниатюры бокового списка шириной до 240 px,
  WebP quality 88, alphaQuality 100.
- `img/blog/cards/` — изображения карточек главной и списка блога шириной
  до 640 px, WebP quality 88, alphaQuality 100.
- `img/blog/previews/` — прежние основные превью статьи и социальных карточек:
  ширина до 1200 px, WebP quality 82. Новое превью создаётся для оригинала
  весом от 200 000 байт. Уже существующие превью сохраняются.

Оригиналы остаются для просмотра в полном размере. Наличие WebP не делает
оригинал ненужным. При публикации загружайте все три папки производных.

Повторный запуск пропускает все существующие производные без проверки mtime:
изменённые при checkout даты файлов не вызывают повторного перекодирования.
После сознательной замены оригинала по прежнему пути обновите только его
производные командой
`node scripts/optimize-images.cjs --force --image=img/blog/имя-файла.jpg`,
затем выполните `npm run build`. `--image` принимает путь из каталога статей;
без `--force` точечный запуск создаёт только отсутствующие файлы.
`--force` без `--image` пересоздаёт производные всех изображений, поэтому
применяйте его только для намеренного массового обновления. При принудительном
обновлении пересоздаётся и уже существующее превью меньшего оригинала.

Сборка добавляет к URL карточек и миниатюр `?v=<12 символов SHA-256>` по
содержимому файла; после замены изображения браузер получит новую версию.
Общие CSS/JS также версионируются. Редактировать URL вручную не нужно:
после оптимизации выполняйте `npm run build`, затем `npm run check`.

Логика статей подключается только на страницах статей перед общим `js/site.js`.
Сборка добавляет связи автора и блога в JSON-LD статей, сохраняя остальные поля.
